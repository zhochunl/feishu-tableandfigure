# 临床试验三线表插件

在多维表格仪表盘的图表区块里，对 AE 之类的记录做**多级分组计数 + 去重计数**，输出三线表，点数字看该组记录，再点「详情」用宿主原生记录卡片打开那条数据。纯前端，不需要后端。

## 扩展形态

装在仪表盘上，占据一个图表区块，和飞书自带图表一样有配置态与展示态。

早前一版这里写的结论是「`@lark-base-open/js-sdk` 没有 dashboard / chart API，只能做边栏插件」——那是当时装的 `^0.3.0` 的结论，错的。`1.0.2` 起有 `bitable.dashboard` 整套消息模块，本插件已升到 1.0.2 并改成仪表盘形态。

状态由 URL hash 的 query 决定（SDK 从 `location.href` 读）：

| 场景 | URL |
| --- | --- |
| 新建图表 | `#/?isCreate=1` |
| 编辑配置 | `#/?isConfig=1` |
| 全屏 | `#/?isFullScreen=1` |
| 展示态 | 无参数 |

配置态显示配置面板，展示态只渲染表；`dashboard.state` 决定这条分支。

「点数据点弹出数据项列表」在这里的正解是 `ui.showRecordDetailDialog({ tableId, recordId, fieldIdList })`——弹的就是宿主自带的记录卡片，不再靠 `bridge.getBitableUrl` 拼深链。

## 使用流程

1. 仪表盘「添加图表」选本插件，进入配置态：左边是预览，右边 350px 是配置面板，面板顶部标的是「分层频率表」。
2. 表头配置（可选）：选一张表头表单（如 DM）。不选列变量就用它的记录数当一个「总计」列的分母；选了列变量（如 `TRT01P`）就每个取值一列。下面的筛选条件先对表头表取子集，列的取值和每列的分母都按筛选后的记录算（如 `SEX = F` 就只剩女性那一批受试者的列）；配了下一步的连接变量时，这批条件还会同步筛明细记录，见第 3 步。
3. 连接变量（配了表头列变量才生效）：指定表头表单与数据表里代表同一含义的变量（如两侧的 `SUBJECT`），明细按它归到各列。两侧只认字段名，不认 fieldId。连上之后（两侧都选到字段就算连上，不必选列变量），表头表里那些明细表没有的变量（如只有 DM 才有的 `TRT01P`、`SEX`）会按连接值补到每条明细记录上，同名变量以明细表自己的为准，一条明细连到多条表头记录时取值取并集。两个下拉左右并排，各占面板一半，不会叠成两行。
4. 数据表配置：选数据表和数据范围（全部数据或某个视图），再配汇总层级——第一层 `AESOC`、第二层 `AEPT`，层数不限，「添加层级」按钮就在这段的最下面。每层可勾「去重」并选去重变量（如 `SUBJECT`）出例数，可勾「百分比」出 n (%)。这里的筛选条件对明细表取子集，例次、例数、百分比都只在子集上算（如 `AETOXGR 属于 3,5` 只统计 3 级和 5 级）。
5. 两块筛选都可以「添加筛选条件」加多条，多条之间是「且」。操作符只有八个，按 大于 / 等于 / 小于 / 大于等于 / 不等于 / 小于等于 / 属于 / 不属于 排列；其中四个大小比较只认数值列和日期列，选了别的字段时这几项在面板里直接灰掉（下拉里保留，方便看懂为什么不能选）。右操作数是一个框两件事：框里直接打字，右边的 ▾ 点开就是**这个变量出现过的全部取值**（按未筛选记录取，最多 200 个，可滚动），单选类操作符点一个就填上并收起，「属于 / 不属于」点一下加一个、再点取消，框里始终是逗号分隔的列表。「包含 / 不包含 / 为空 / 不为空」已下线。
6. 点「保存配置」，配置写回宿主，退出配置态后展示态按同一份配置渲染。
7. 标题行只有一行：最左边一个单元格里把分组变量自上而下一行一个写出来（第二层起按层级缩进），整块和右侧的列标题上下居中对齐；列标题（试验组、对照组、总计）水平居中在数据块上方，标题下面一行是该列的大 N（分母，取表头表这一列的记录数；没配表头就没有分母，也就不写 N）。最右边固定一列总计，配不配列变量都有。标题行和顶线、底线一起钉在图表面板上，只有中间的数据区滚动，标题行上方不再有表名、行数之类的描述文字。
8. 表格按例次降序展示，父层可折叠；一格里是「例次（例数）百分比」，三个数字属同一个数据块，点任意一个都弹出该组该列的例次记录列表，点行打开宿主原生记录卡片。

变量下拉的顺序跟数据表里的列顺序一致（表级 `getFieldMetaList` 不保证顺序，插件按视图的有序字段列表校正）。

## 配置怎么存

`dashboard.saveConfig` 存两份，宿主浅合并 `{...已有, ...payload}`：

- `dataConditions`：`tableId`、`dataRange`、每层 `groups`（`GroupMode.ENUMERATED` 多选拆开统计）、`series: 'COUNTA'`。这让宿主的数据源和分组跟插件保持一致。
- `customConfig.aeThreeLine`：`{ version: 3, tableId, dataRange, levels, filters?, header?, join? }`，`levels` 是 `{ fieldId, dedupe, distinctFieldId, percent }`，`header` 是 `{ tableId, fieldId?, filters? }`，`join` 是两侧的 fieldId，两处 `filters` 都是 `{ fieldId, operator, value }` 数组，`value` 存的是字符串，属于/不属于用逗号分隔。全部用 **fieldId** 而不是字段名，字段改名不丢配置。

跨表连接、去重和筛选条件宿主都算不了，所以只存在于 `customConfig`；`dataConditions` 里没有表头表的痕迹。读回来时 `customConfig` 优先，缺了就退回 `dataConditions[0].groups`（丢失去重、分列、百分比与筛选口径），两者都没有 `tableId` 才算未配置。v1、v2 配置照样能读，只当没有筛选；v1 没有去重开关，配了 `distinctFieldId` 就视作勾选去重。八个操作符都要填值，存之前 `normalizeFilters` 会丢掉没选字段、操作符不认识（含已下线的「包含 / 为空」这类）和值空着的条件；某条条件是不是大小比较要等字段元信息才知道，那一步交给 `resolveFilters`。

**计数为什么必须本地读记录**：宿主的 `Rollup` 只有 `SUM / AVERAGE / MAX / MIN`，没有去重计数，而且 `getData` 返回的 `IDataItem` 不带 `recordId`。所以例数和钻取都要求插件自己持有记录集合，不能只信宿主算好的聚合值。

## 计数口径

- 列来自表头配置：不配表头只有一列「总计」且没有分母；配了表头不选列变量是一列「总计」（分母=表头表记录数）；选了列变量就是每个取值一列，再在最右边固定一列「总计」（分母=表头表全部记录数）。这个分母就是列表头下面的大 N，跟百分比用的是同一个数。
- **筛选先于计数**：配了连接变量后，表头表的筛选条件在补过变量的明细上照样算，所以 `TRT01P 等于 试验组` 既裁掉列和分母，也裁掉对照组受试者的 AE 记录，总计不会再出现 196.7% 这种分子分母不同口径的数字。数据表的条件决定哪些明细记录参与例次/例数，表头表的条件另外决定有哪些列和每列的分母。多条条件之间是「且」，一条条件里多选字段只要有一个值命中就算命中；大小比较先试数值，两边都是 `YYYY-MM-DD` 形式的日期时才按日期文本比。
- **例次** = 该组该列内的记录条数，一条 AE 记录算一次。
- **例数** = 该组该列内去重字段的不同取值个数，只有勾了「去重」的层才出这个括号。
- **百分比** = 分子是勾了去重时的例数、否则例次，分母是该列的 total；所以同组各列之和可能超 100%（多选展开）。没配表头时没有分母，百分比不显示，勾选框也会禁用。
- 父层的例数是父层自身记录集合去重的结果，**不是**把各子层的例数相加。所以同一个受试者在同一 AESOC 下的两个 AEPT 各发生一次，父层仍算 1 人。
- 去重字段为空的记录不计入例数（无法归属到具体对象），但仍计入例次。
- 分组字段是多选时，一条记录同时计入它的每个取值，因此各组之和可以大于总例数——这是 AE 汇总的常规口径。
- 分组字段为空归到「缺失」组，固定排在最后。
- 分列时按连接变量归列，连接不上表头表的记录不进任何分组列，但照样算进最右边的总计列；界面上不再单独提示有多少条。这些连不上的记录也没有补到表头专有变量，`等于 / 属于`类条件不会命中它们，`不等于 / 不属于`类会命中，按需求取舍。

## 单元格到分组的转换

读表阶段就把单元格归一化成文本，界面与汇总只看字段名，不接触原始结构：

| 字段类型 | 取值方式 |
| --- | --- |
| 单选 | 取 `text` |
| 多选、人员、群 | 逐项取 `text` / `name`，展开成多个值 |
| 日期、创建/修改时间 | 毫秒戳格式化成 `YYYY-MM-DD`，带时分时补时间 |
| 复选框 | 是 / 否 |
| 自动编号 | 取 `value` |
| 文本、数字、URL、电话 | 原样 |
| 空值 | 空数组，归到「缺失」 |

## 数据读取

- 字段元信息用一次 `getFieldMetaList` 拿全，不逐字段 `getName`/`getType` 往返。
- **变量下拉的顺序按表内列顺序**：`table.getFieldMetaList()` 不保证顺序，插件改问 `view.getFieldMetaList()`（SDK 注明有序），表级那份只用来补全视图里没显示的字段；问不到视图时退回表级顺序。
- 表头表是独立的一次读取（字段 + 全表记录），用来算列和分母，并把表头专有变量按连接值补进明细；换表头表不会重读明细表。
- **筛选条件在本地做**：宿主的 `getRecords` 不接受任意 filter，`Rollup` 的条件也只支持单表，所以条件是在读回来的记录集合上取子集，不回宿主重读；换条件不重新取数，但也不影响已经读进来的行数统计。字段的候选取值同样从**未筛选**的记录里取。
- **明细段的筛选可选表头专有变量**：数据段的字段列表是明细表字段再并上表头表里那些明细表没有同名字段的字段（只有连上连接变量才并入），所以 `TRT01P`、`SEX` 这类只在 DM 里有的变量也能在明细侧加条件，▾ 里的取值来自补过的明细记录。表头段的条件仍按表头 fieldId 解析，翻成字段名后在补过的明细上算。
- 数据范围是视图时，`viewId` 直接透传给 `getRecords`，筛选交给宿主做；`filterInfo` 原样保存在配置里。
- 记录用 `getRecords` 分页读，单页从 1000 起步；只有单页条数被拒时才沿 1000 → 500 → 200 → 100 降档重试，其它错误直接抛出。
- 读完只保留归一化后的文本，钻取用的明细也来自这份内存数据，**点数字不会再回宿主取记录**。
- 行内存活上限受多维表格版本限制（基础版/商业标准版 2000 行，商业专业版 2 万行，商业旗舰版/企业版 5 万行），但读多少行就占多少浏览器内存，几万行的 AE 表请留意。
- 每次渲染完调 `dashboard.setRendered()`；独立打开页面（没有宿主）时这个调用会失败，吞掉。

## 本地开发

```bash
npm install
npm run dev      # http://127.0.0.1:4173
npm test         # 跑五个回归套件
npm run build    # 产物在 dist/
```

联调台在 `http://127.0.0.1:4173/devtools/mock-host.html`：它模拟仪表盘宿主，内置一张 mock AE 表（单选 AESOC、多选 AEPTMOD、日期、两个视图、2% 空值）和一张 DM 表（含 `TRT01P` 试验组/对照组，用来验证表头分列与连接变量），可以调记录数、受试者数、AESOC 数、多选占比，还能把宿主单页上限调小来验证分页降档。改完参数点「重建数据并重载」。

字段顺序也做了专门处理：`WidgetTable.getFieldMetaList` 故意倒着返回，只有 `WidgetView.getFieldMetaList` 给有序列，插件要靠视图拿顺序、再用表元信息补全隐藏字段；下拉乱了或少列，先看 mock 日志里 `WidgetView.getFieldMetaList` 有没有被调到。

筛选也有现成的靶子：mock 的 DM 表里 `SEX` 和 `TRT01P` 严格配对（奇数号受试者是 `F` / 对照组），默认 60 个受试者、每列分母 30，列表头就是「试验组 N=30 / 对照组 N=30」。表头条件写 `SEX 等于 F` 就只剩「对照组」一列，其余列整个消失，同时因为 `SEX` 已按 `SUBJECT` 补进 AE 明细，各格数字（含总计列）只统计女性受试者，百分比不会超 100%；明细条件写 `AETOXGR 属于 3,5` 只统计 3 级和 5 级，各格数字明显变小，明细段的变量下拉里也能直接选到 `TRT01P`、`SEX`。`AETOXGR`、`AESTDT` 分别是单选和日期列，可以拿它们验证「大小比较只对数值/日期开放」，再换 `AESOC` 看这四项灰掉；换 `SUBJECT` 则能验证下拉里一次列出 60 个取值。

状态切换靠重设 iframe 的 hash，联调台选「新建配置 / 修改配置 / 全屏 / 展示态」即是切 `#/?isCreate=1` 等；`savedConfig` 是宿主唯一的配置来源，「查看」能把 `saveConfig` 收到的 payload 打出来核对往返。「记录卡片」计数验证钻取走的是 `UI.showRecordDetailDialog`。

SDK 的 key 形如 `bitable.Dashboard_getConfig`，所以 mock 宿主先取最后一个 `.` 之后的串，再按第一个 `_` 拆模块和方法。

## 已知限制

- 分列只支持「一张表头表 + 一个连接变量」的关联，连接按**字段名**匹配（两张表的 fieldId 体系不同），两侧字段名任一个被删掉就整体退回不分列，表头专有变量也不再补进明细，不静默错算。
- 表头表只取全表记录算列与分母，不受数据表的视图筛选影响。
- 一列的 total 是该列表头记录数；如果同一受试者在表头表里出现多行，分母会按记录数而不是人数。
- 数据是一次性快照，不订阅表变更；宿主在图表上配的独立筛选器对本插件无效。改完记录要重新进配置态保存或刷新。
- 筛选条件在本地取子集，前提是把整表读进内存：数据范围是视图时先受宿主视图筛选，再叠加本插件的条件。大小比较先试数值，两边都是 `YYYY-MM-DD` 时才按日期文本比；比不了的（比如纯文本字段）在 UI 里就灰掉、在解析时整条作废，宁可不筛也不按字典序错筛。
- 换了数据表或表头表，绑在旧表 fieldId 上的筛选条件一并作废，不会静默按不存在的字段计数；字段被删的单条条件直接不生效（宁可少筛不可错筛），参与统计的行数会回到未筛选的数量。
- 每次数据源变化都整表重读一遍，大表在配置态来回切会慢。
- 弹窗列表最多渲染前 200 条。
- 标题行只有一行，但高度跟层级数走（两层约 41px），且和底线一起冻结在面板内；把图表的显示高度调得很矮时，剩下的可视行数会被压缩得只剩几行。
- 展示态的表名来自 `listTables()`；宿主换了表又没重新保存配置时，标题会退回显示 `tableId`。
